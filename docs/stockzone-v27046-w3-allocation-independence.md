# StockZone v2.7.0.46 — W3／動態倉位資料依賴根本修正

## 問題及根因

v2.7.0.45 的五年 R1 已可跳過歷史公司行動造成的價格斷層，但動態倉位在 `lib/resonance-lab-v1.js` 的 `api.cleanBars` 包裝器仍透過 `res.valid` 對整份五年 K 線設閘。歷史中任一筆大幅跳價，會將動態倉位的近期 OHLC 緩衝整個清空，導致 `contextAt` 無有效日期。隨後舊 W3 UI 讀取程式把 W3 日期強制與此不存在的個股日期相比，錯誤顯示「W3尚未確認」。

## 處理內容

1. 保留五年 R1 全歷史取樣（含異常隔日重取）、五策略原始函式與計算門檻。
2. 動態倉位改由 `recentAllocationContext` 只取最後 **120 根有效且自洽的近期 K 線**，直接重用原版 `cleanBars`、`contextAt`；不重建或調整 OHLC。最後 120 根內如有 >35% 跳價、OHLC 不正確、重複日期或無法辨識日期，拒絕倉位計算。
3. `app.js` 的同一份大盤動態資料提供 `StockZoneGetOfficialW3`，與大盤卡共用原有 `stockzoneW3Regime`、`marketStableTradeDate` 的邏輯，保留正式 W3 過期／非即時模型的拒絕條件；不讀取 DOM 顯示文字，亦不由個股日 K 判定 W3 是否存在。
4. 正式 W3 已確認但近期股價日期不同步（差距超過 7 天）時，保留 W3 狀態顯示，停止倉位計算，明示近期價格不一致原因。
5. 用 `stockzone:w3-current` 更新事件連動畫面；搜尋不同股票時同步清理舊緩衝，避免跨股資料混淆。
6. 維持正式 V4 倉位基準、W3 OFF／預警策略分支、交易計畫鎖定、API、Neon、XY、W3-D.1.2 原始公式不變。

## 驗證

`npm run validate:release46`

測試含：完整五年、歷史斷層／近期正常、近期 35% 跳價、OHLC 無效、缺乏 120 根、正式 W3 ON／WARNING／OFF／過期、股價／W3 週期差異、跨股票切換、`.45` 既有回歸測試、授權、排程、版號與部署設定。

## 啟用／回滾

直接將 CHANGE ONLY 覆蓋 v2.7.0.45 原目錄並部署，無須變更 Neon、XY 或 W3。這個版本未修改 `vercel.json` 和 `proxy.js`。若 Vercel 正式環境異常，可恢復最後成功版本；不要修改資料庫或舊日 K。

未做線上 Vercel 實機測試，長榮實際 2026-10-30 的近期 120 根日 K 與 V4 配置基準，仍需部署後核對。只有近期價格與 V4 基準足夠時，才會顯示比例；不保證每檔股票都能計算倉位。
