# 開發者模式統一上鎖（預留，未啟用）

目前版本**不要求輸入產業異動管理密鑰**。此項原本只鎖「產業異動」的單獨密鑰已退出前後端流程。

## 未來如要重新加入保護

一次保護**整個開發者模式**：所有修復／管理／候選異動／手動掃描／資料庫稽核／快照更新等，不是只保護單一小卡。

- 伺服器端為所有開發者專用的 API **統一**驗證身份／權限，不能只隱藏畫面或在 JS 放密碼。
- 前端進入「開發者模式」時統一登入；已解鎖期間不再對每個功能重複索取。
- 每一條開發者 API 都應拒絕未認證寫入；Cron 則維持獨立 CRON_SECRET。
- 避免把 STOCKZONE_DEV_SECRET 寫在 GitHub 或前端，改使用伺服器密鑰及 HttpOnly、Secure、SameSite cookie。
- 請不要將目前的同源檢查誤認為權限驗證。當前開發者模式仍可由網站使用者操作候選異動。

## 本次維持的鐵證安全邊界

1. 產業異動只保存於獨立 Private Blob，並不寫入 Neon 正式分類。
2. 尚未導入的候選不可刪除；「已導入」必須來自 Neon 的正式 release 證據及對應真實分類。
3. 產業異動 API 不提供 `confirm` 或正式分類寫入操作。
4. Neon 的核心／相關修改仍須 SZ-鐵證完成後由獨立工具寫入。

## 部署前提

仍需要 `BLOB_READ_WRITE_TOKEN` 與 Cron 的 `CRON_SECRET`。`STOCKZONE_DEV_SECRET` **不再用於產業異動**（如果其他後端模組有使用則不可隨意刪除）。
